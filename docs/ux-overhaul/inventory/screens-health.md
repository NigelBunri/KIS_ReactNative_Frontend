# Health Domain Inventory — `src/screens/health/**`, `src/components/health/**`, `src/components/healthcare/**`

**Status: Phase 1 (inventory only). No code was edited. 54/54 assigned files inventoried (44 in `src/screens/health/**`, 8 in `src/components/health/**`, 2 in `src/components/healthcare/**`). Nothing unreachable.**

This is one of the most sensitive domains in the app: emergency/SOS, mental health, addiction recovery, maternal/pregnancy tracking, medications, and a full clinical/institution-operations suite (EHR, e-prescription, admissions, billing). Route names were cross-referenced against `/Users/nigel/dev/KIS/App.tsx` (registration) and `/Users/nigel/dev/KIS/src/navigation/types.ts` (param types) rather than `src/navigation/AppNavigator.tsx`, per the standing note that routes live in root `App.tsx`.

Two screens in the flat `src/screens/health/` directory are **not wired into any navigator and not imported by any other file**: `HealthInstitutionsScreen.tsx` and `InstitutionOnboardingScreen.tsx`. They appear to be superseded by `InstitutionsListScreen`/`HealthInstitutionManagementScreen` and the institution-onboarding flow elsewhere, but they are live, compiling source files sitting dead in the tree — worth flagging for the audit, not for this pass to touch.

Emotional/trust observations (documentation only, no fixes made):
- `emergency/EmergencyScreen.tsx` deliberately avoids false reassurance: its SOS confirmation copy has an inline code comment explaining the team chose *not* to promise "help is on the way" because no contact-dispatch pipeline exists yet, and the alert text tells the user to call local emergency services directly. This is a good trust pattern, but the screen's header and SOS button both use `palette.danger` (red) as the dominant color for a screen a user may open while already distressed — worth a later pass on whether a calmer visual treatment (reserving red only for the SOS button itself) would reduce alarm.
- `symptoms/SymptomCheckerScreen.tsx` is explicitly labeled "(Beta)" with a persistent disclaimer ("general guidance only... always consult a qualified healthcare professional") and a `triage_level`/`disclaimer` field returned from the backend — good practice for an AI-driven symptom tool.
- `mental/*` and `recovery/*` screens use neutral, non-shaming copy in the parts read (no "you failed/relapsed" language found); `SobrietyTrackerScreen.tsx` frames progress as "Since {date}" plus sponsor/accountability-partner contacts rather than a punitive streak-reset message — but the reset/slip path itself wasn't fully traced in this inventory pass and should get a closer look when the mental/recovery screens are audited in depth.
- `HealthEnginesDashboads/EmergencyDispatchManager.tsx` is a *staff-facing* ambulance-dispatch console (not patient-facing), using `AmbulanceStatus`/`EmergencyPriority` typed states — tonally fine since its audience is clinical staff, not a patient in crisis.
