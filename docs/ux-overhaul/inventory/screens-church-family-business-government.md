# Screen Inventory — church / family / business / government

Phase 1 (inventory only — no code edited). Scope: `src/screens/church/**` (18 files), `src/screens/family/**` (16 files, incl. `components/FamilySelect.tsx`), `src/screens/business/**` (13 files), `src/screens/government/**` (12 files). **59/59 files inventoried.** Route names were cross-referenced against `/Users/nigel/dev/KIS/App.tsx` (registration lives there, not `AppNavigator.tsx`) and `/Users/nigel/dev/KIS/src/navigation/types.ts`.

All screens use the shared pattern: `SafeAreaViewWithTopPadding`, `useKISTheme`/`useResponsiveLayout`, `getRequest`/`postRequest`/`patchRequest` against `ROUTES`, and `NativeStackScreenProps<RootStackParamList, '<RouteName>'>`. Deviations are called out per-row.

**Two orphaned/dead files found in `business/`:** `JobsScreen.tsx` and `MyApplicationsScreen.tsx` are not imported by `App.tsx` or anywhere else in `src/`. The live, routed versions for `JobsBoard` and `MyApplications` live in `src/screens/jobs/JobsBoardScreen.tsx` and `src/screens/jobs/MyApplicationsScreen.tsx` instead — separate, diverged implementations (different status enums, different nav typing, different fields). The `business/` copies appear to be superseded leftovers. Flagged below as "not registered" with a dead-code note.

**No pull-to-refresh anywhere in church, family, or government** (0 of 46 files use `RefreshControl`); all rely solely on `useFocusEffect` refetch-on-focus. Business is the only domain with `RefreshControl`, and only in 6 of 13 files (`CoWorkingScreen`, `CrowdfundScreen`, `JobsScreen`[orphaned], `MentorshipScreen`, `MyApplicationsScreen`[orphaned], `SavingsGroupsScreen`) — so even there it's inconsistent and the two files that do have it aren't live.

**Payment/money UX pattern (flagged per instructions):** every money-entry screen (`GiveNowScreen`, `ChurchPledgeScreen`, `CrowdfundDetailScreen` contribution form) submits immediately on button press and shows a post-hoc `Alert.alert('Thank You' / 'Contribution recorded!', ...)` — there is no pre-submit confirmation step (no "You are about to give $X — confirm?" dialog) before the monetary action is recorded. Amounts are validated for being numeric/positive but not re-displayed for confirmation before the request fires. Worth a closer look in a later UX phase.

## Notes for later phases

- **Dead code**: `src/screens/business/JobsScreen.tsx` and `src/screens/business/MyApplicationsScreen.tsx` are unreferenced anywhere in `src/` or `App.tsx`. The live routes `JobsBoard` and `MyApplications` resolve to `src/screens/jobs/JobsBoardScreen.tsx` and `src/screens/jobs/MyApplicationsScreen.tsx` respectively — confirmed via `grep` for both import paths and route registrations. These two `business/` files should probably be deleted or reconciled with the `jobs/` versions in a cleanup pass (out of scope for this inventory).
- **No pull-to-refresh** in church/family/government (46 files, 0 hits for `RefreshControl`); business has it in 6/13 files but 2 of those are the orphaned dead files above, so only 4 live business screens actually support pull-to-refresh.
- **Payment confirmation gap**: `GiveNowScreen`, `ChurchPledgeScreen`, and `CrowdfundDetailScreen` all submit monetary amounts immediately on button press with no pre-submit "confirm this amount" step — only a post-hoc thank-you `Alert.alert`. Worth checking `SavingsGroupDetailScreen`'s contribution flow too (file truncated at header read — no Alert/catch found by grep, suggesting it may be read-only or use a different submission path not yet located).
- `GovernmentHubScreen.tsx` is the only hub screen across all four domains with zero data-fetching hooks/state — purely static navigation, unlike `ChurchScreen`, `FamilyHubScreen`, and `BusinessHubScreen` which all fetch an overview via `getRequest`.
- `FamilySOSScreen` (route `FamilySOS`) is a safety-critical emergency-alert screen — worth prioritizing in interaction/accessibility review given its purpose.
