# Broadcast / Channels Inventory — `src/screens/broadcast/**` + `src/components/broadcast/**`

**Coverage: 136 of 136 assigned files inventoried (118 under `src/screens/broadcast/**` + 18 under `src/components/broadcast/**`).** All files were read (full or substantial head/body reads) and cross-referenced against `App.tsx`'s `RootStack` + deep-link `linking` config and `src/navigation/types.ts` for route registration, plus `grep`-based import-graph checks to determine reachability. No files were skipped. This is a pure read-only inventory — no source files were edited.

**Context already established by the prior full-system analysis** (`docs/broadcast-channels-analysis-PROGRESS.md`, synthesized into the "Broadcast & Channels Closure" artifact, 2026-10-04) and **not re-reported here as new**: the 8 confirmed "broadcast"/"channel" naming collisions; the dead `src/hooks/useBroadcastFeed.ts` + `src/types/broadcast.ts` stack (reachable only via the orphaned `FeedsListScreen`/`FeedsNavigator`, which are **outside** this scope); gallery/replay content-type gaps, RSVP backend, and ad-auction-engine gaps on the Django side; the Channel Studio tier-gate bug (already fixed); the institution-channel notification gap; the stale Mux comment; Django admin coverage gaps (live streams/copyright/ads/monetization unregistered). None of those are repeated below except where this pass found a directly adjacent, previously-unreported detail.

## Three newly identified dead-code clusters in this scope (not in the prior analysis)

1. **`src/screens/broadcast/market/*` dead cluster (12 of this scope's files).** `BroadcastMarketPage.tsx` (registered as the Broadcast tab's "market" sub-tab, and the one actually live) is a fully self-contained, separate implementation. The entire sibling cluster — `MarketSection.tsx`, `api/market.endpoints.ts`, `api/market.types.ts`, `components/MarketProductCard.tsx`, `components/MarketShopCard.tsx`, `components/MarketTabPills.tsx`, `hooks/useMarketData.ts`, `pages/MarketDropsPage.tsx`, `pages/MarketHomePage.tsx`, `pages/MarketInsightsPage.tsx`, `pages/MarketProductsPage.tsx`, `pages/MarketShopsPage.tsx` — has **zero importers anywhere in the app** (verified via `grep -rl` from the repo root and `App.tsx`). Only `ProductDetailsPage.tsx` (route `ProductDetail`) and `pages/ShopProductsPage.tsx`/`pages/ShopServicesPage.tsx` (routes `ShopProducts`/`ShopServices`) are live and registered.
2. **`src/components/broadcast/BroadcastFeedSection.tsx` — 2,103 lines, zero real importers.** The only two hits for its name anywhere else in the repo are a stray code comment in `src/navigation/AppNavigator.tsx` and a stray comment in `MarketStudioSection.tsx` — neither is an actual import. This looks like a predecessor to the live `BroadcastFeedCard.tsx` + `FeedsMainListSection.tsx` pairing, left in place after a rewrite.
3. **`src/components/broadcast/MarketStudioSection.tsx` (1,186 lines) and `src/components/broadcast/RecommendationsSection.tsx` (274 lines) are both dead.** `MarketStudioSection` is imported only by the dead `MarketProductsPage.tsx` (cluster #1) and the dead `BroadcastFeedSection.tsx` (#2) — both unreachable, so it is transitively dead too. `RecommendationsSection` has no importers at all, anywhere, including itself.

Combined, **15 of the 136 assigned files (≈11%) are confirmed unreachable dead code** — a materially larger finding than anything the prior analysis flagged for this specific directory scope.

## Other structural notes

- **`src/screens/broadcast/education/**` (9 files) is not private to the Broadcast tab.** `EducationContentCard`, `EducationContinueLearning`, `useEducationDiscovery`, `educationAccess.ts`, and `education.models.ts` are all also imported directly by the separate Education UX v2 learner screens (`src/screens/education/learner/EducationHomeScreen.tsx`, `CourseDetailScreen.tsx`, `MyLearningScreen.tsx`, `CertificatesScreen.tsx`, `LearningPlayerScreen.tsx`) and even by Partner-panel code (`src/screens/tabs/partners/PartnerPanels.tsx`, `usePartnerProfileLinks.ts`, `src/components/partners/PartnerLinksPanel.tsx`). This subfolder is shared platform infrastructure living under `broadcast/`, not a scoped-down duplicate.
- **Channel Studio (`studio/*`, 23 files) is reachable but not via any `RootStack` route.** `ChannelStudioScreen.tsx` is rendered only from `FeedManagementModal.tsx` (a modal opened from `ProfileScreen.tsx`); none of its 20 tabs/panels are independently routable. `studio/LiveGuestRedeemScreen.tsx` is the one exception — it IS a real route (`LiveGuestRedeem`, deep link `live-guest/:token`).
- **`channels/components/*` (21 files) and `channels/api|hooks|embed/*` (6 files) are all non-routable support files** — embedded inside `ChannelContentDetailPage`, `LiveWatchPage`, `ShortsScreen`, `MembershipScreen`, etc., or pure data/socket layers. None appear in `RootStack` or `linking` directly.
- **`AgeGateScreen.tsx` carries an explicit non-security disclaimer in its own header comment**: it is "pure client-side self-attestation... never enforced server-side, because the User model has no birthdate field." Flagged by the component author already, repeated here because it's a real UX/trust-surface gap (age-restricted content is effectively ungated).
- **`BroadcastHealthcarePage.tsx` and `BroadcastJobsPage.tsx`** are full standalone implementations (1,292 and 272 lines) living under `pages/`, not alternate tab-content wrappers around other systems — Healthcare delegates part of its body to `SoloPractitionerDashboard` from `src/screens/health/`.
- Several of the "media_extended" screens (`CreatorAnalyticsScreen`, `EbooksScreen`, `KingdomMusicScreen`, `KingdomNewsScreen`, `PPVEventsScreen`, `PodcastsScreen`) are structurally near-identical (same imports, same `NativeStackScreenProps` + `useFocusEffect` + `LinearGradient` header shape) — likely scaffolded from a shared template; worth checking in a later consolidation pass whether they should share one generic "media catalog" screen component instead of six copies.
