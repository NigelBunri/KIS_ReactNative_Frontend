## Notable observations

1. **Testimony feature shares a lot of duplicated boilerplate.** All six `src/screens/testimony/**` files independently redeclare identical `CATEGORY_LABELS` and `CATEGORY_EMOJI` constant maps (health/finances/relationships/faith/business/grief/addiction/family/mental_health/other). This is a clear consolidation candidate for a later phase, and worth flagging since UX consistency (copy, emoji) depends on these staying in sync across six copies.

2. **Website-builder screens are unusually consistent and well-factored.** All ten screens follow the same shape — `getHealthThemeColors('light')` + `HEALTH_THEME_SPACING`/`HEALTH_THEME_TYPOGRAPHY`, `loading`/action-specific booleans, try/catch/finally fetch pattern, `SafeAreaView` from the same wrapper. Two screens (`WebsiteFormResponsesScreen`, `WebsiteVisitsScreen`) conspicuously lack any `Alert`/error-catch pattern that its siblings have — worth a closer look in the audit phase for whether failed loads surface anything to the user at all.

3. **Several files use direct S3-via-Nest upload (`uploadFileToBackend` + `NEST_API_BASE_URL`) for image-only assets** (website logo in `WebsiteThemeScreen`, website builder section images, partner app icons in `OrganizationAppFormScreen`), explicitly commented as bypassing Django's profile-attachment endpoint because there's no video-processing dependency for image-only pickers. This is a deliberate architectural split worth keeping in mind if the audit touches upload UX — the error-handling shape differs slightly (e.g. `WebsiteThemeScreen`'s `uploadLogo` silently falls back to the local `asset.uri` on failure rather than surfacing an error).

4. **Two deep-link "auto-action" screens exist with near-identical idle/loading/success/error state machines**: `InviteJoinScreen` (`join/:type/:token`) and `PartnerRedeemInviteScreen` (`join/partner/:code`), both using a fade-in `Animated.Value` and auto-triggering their primary action in a `useEffect` on mount. Good candidates for shared pattern extraction, and both are relevant to any consistency review of "deep link landed, now show status" UX.
