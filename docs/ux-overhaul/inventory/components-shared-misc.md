# Inventory: `src/components/{feeds,sections,section-builder,dashboard,shell,common,profitability,media,verification}/**` + root-level `src/components/*.tsx`

**Scope:** Feed/post rendering + rich-text composer (31), website-builder static section renderers (20), website-builder authoring UI (12), GO-only Profile admin dashboard cards (14), tablet/desktop responsive shell chrome (12), cross-app shared primitives (11), revenue-preview cards (10), loading-aware media wrappers (3), trust/verification UI (3), and 3 root-level singletons (`ControlPanelLinkCard`, `KISFab`, `SyncQueueBanner`).

**Count:** 119 of 119 assigned files inventoried (31+20+12+14+12+11+10+3+3 = 116 across the nine subfolders, + 3 root-level files = 119). 0 files remain NOT YET INVENTORIED.

**Reachability — headline findings:**
- **`src/components/common/` and the 3 root files are the real shared design-system primitives for this batch**, exactly as expected going into Phase 4. `SafeAreaViewWithTopPadding` (211 referencing files), `KISText` (49), `Skeleton` (27), `KISFab` (31 consumers across chat/community/broadcast/messages/insights), `ImagePlaceholder` (14) are genuinely high-reuse, load-bearing primitives. By contrast `MainTabScaffold`/`MainTabPageHeader` is only used by `ProfileScreen.tsx` despite living in `common/` — a one-off that should probably not be presented as a shared primitive in Phase 4, or should be adopted more broadly if it's meant to be the standard main-tab header.
- **`src/components/profitability/**` (10 files) is a near-total facade.** Every single file is a byte-for-byte-identical stub: `export default function X(_props) { return null; }`. 6 of the 10 are actually imported into real screens (ShopDashboardScreen, BroadcastMarketPage, ProductDetailsPage, BibleScreen, ChannelStudioScreen, HealthInstitutionCardsScreen, InstitutionServicesCatalogScreen, ProfileNotificationsScreen, KcanVisionModal) where they silently render nothing — i.e. there are real screens today with a revenue-preview-card-shaped hole in their UI. The other 4 (`CompactProfitabilityPreviewCard`, `EducationRevenuePreviewCard`, `InstitutionMonetizationPreviewCard`, `PartnerRevenuePreviewCard`) aren't imported anywhere at all.
- **4 of the 14 `dashboard/` cards are fully dead** (not imported anywhere): `AIAssistanceSafetyCard`, `PerformanceOfflineCard`, `PublicGrowthReadinessCard`, `UnifiedDashboardSummaryCard`. The other 10 are all mounted together in one GO-only admin block inside `ProfileScreen.tsx` (~line 2950-2959).
- **`src/components/section-builder/SectionBuilder.tsx` itself is dead** — defines `addSection`/`updateSection`/`removeSection` but voids all three (`void addSection;` etc.) and is never imported by anything; `WebsiteBuilderScreen.tsx` instead composes `SectionTypeSelector` + `DynamicSectionForm` + `SectionPreview` + the picker modals directly, bypassing this wrapper entirely.
- **`src/components/feeds/FeedCommentsScreen.tsx` is dead** — not imported anywhere; `CommentThreadScreen.tsx` and `BroadcastFeedCard.tsx` use `CommentThreadPanel` directly instead.
- **Duplicated logic found:** `src/components/feeds/composer/richUtils.ts` (95 lines) and `richTextUtils.ts` (341 lines) both define near-identical `computeEditDelta`/`shiftSpans` functions. `richUtils.ts` is only consumed by `docConversion.ts`; `richTextUtils.ts` is the one actually used by `TextComposerPage.tsx`. Worth a Phase-4 dedup flag.
- **`src/components/feeds/composer/featuresRegistry.ts`** defines a `notYet(label)` helper whose `run` calls `ctx.toast('${label} (ready-to-wire)')` — several toolbar actions in the rich-text composer are explicit stubbed/unwired placeholders, not finished features.
- **`sections/**` (website-builder renderers) are intentionally static/read-only mockups** for several section types (Embed, Form, Slideshow, PromoBar, KisContent) — each docblock explicitly states the *real* rendering only happens on the published website (`components/website-builder/SectionRenderer.tsx` in the separate website repo), not in this app. This is "by design," not a bug, but worth noting for Phase 4 so nobody flags these as broken interactivity.
- `media/LoadingImage` and `media/LoadingPdf` are each used by exactly one screen (`MaterialViewer.tsx`) — low reuse despite being generically named/designed as drop-in wrappers; `PermanentRemoteImage` is more broadly used (12 files).
- `shell/**` is confirmed live infrastructure: `ResponsiveContainer`/`TabletShell` is wired into `AppNavigator.tsx` and `App.tsx` directly, and `TabletDialogOverlay` is used by `App.tsx` for the gold-header-hoisted overlay system; `Sidebar`/`ContextPanel`/`TabletLayout`/`DesktopLayout` form one coherent >=768dp shell.
- `verification/**`: `VerificationCenter.tsx` exports `VerificationBadgeRow`, `VerificationCenterSheet`, `VerificationStatusCard` (multiple named exports from one file) each with its own distinct consumer set (4-6 files); `VerificationStaffConsole` is GO/staff-only tooling (2 consumers).
