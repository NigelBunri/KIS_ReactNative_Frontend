## Legacy vs. active — verdict: ACTIVELY MAINTAINED CORE INFRASTRUCTURE, not legacy

This directory is **not** a parallel/legacy structure being migrated away from. It is live, heavily-depended-on plumbing for three of the app's biggest features (chat, communities/channels, and broadcast video), and it is where real recent bug fixes landed (the "4 root-cause chat structural fixes" from prior project memory — receipt shape, StyledText types, SendMessageDto fields, persist() timing race — all live in `src/Module/ChatRoom/hooks/useChatPersistence.ts` / `useChatMessaging.ts` / `chatTypes.ts`). Evidence:

- `App.tsx` (root) directly imports and mounts four `src/Module` screens as stack routes: `ChatRoomPage`, `ChatInfoPage`, `CommunityRoomPage`, `CommunityInfoPage` (lines 78–81, rendered at lines 460–506).
- `ChatRoomPage` is also imported/used from `src/screens/tabs/MessagesScreen.tsx`, `src/screens/tabs/feeds/BroadcastDetailScreen.tsx`, `src/screens/partners/OrganizationAppScreen.tsx`, `src/components/partners/PartnersMessagesPane.tsx`, `src/components/partners/PartnerMessagingView.tsx`, `src/components/shell/TabletDialogOverlay.tsx`, `src/push/notificationRouter.ts`, and `src/screens/tabs/MesssagingSubTabs/callsTabHelpers.ts`.
- `src/Module/AddContacts/AddContactsPage.tsx` and its sub-forms (`NewGroupForm`, `NewCommunityForm`, `NewChannelForm`) are mounted from `MessagesScreen.tsx`, `CommunitiesTab.tsx`, `HealthInstitutionMembersScreen.tsx`, `ShopDashboardScreen.tsx`, `PartnerCreatePanel.tsx`, and `UpdatesTab.tsx`.
- `src/Module/vieo`'s `KISVideo` component (the app's actual video-playback primitive, wrapping `react-native-video`) is used by `ShortsScreen.tsx`, `PlaylistDetailScreen.tsx`, and `BroadcastFeedVideoPreview.tsx` — i.e. it **is** the broadcast/shorts video player, not a legacy alternative to one.
- Test coverage exists and reads as live regression protection, not abandoned scaffolding: `directConversationIdentity.test.ts`, `normalizeConversation.pagination.test.ts`, `normalizeConversation.errorStates.test.ts`, `buildTimelineItems.test.ts`, `voiceAttachment.test.ts`, etc. each document a specific real bug (e.g. two call participants seeing the same name, conversation pagination silently dropping pages past page 1) that was found and fixed here.
- File-header comments (`// src/screens/chat/...`) on many files are stale relics of an earlier physical location (`src/screens/chat/`) that the code was moved out of into `src/Module/ChatRoom/` — a sign of internal reorganization, not deprecation.

**However, three individual files inside the module are dead/orphaned** (see Audit Status notes below) — these should be flagged for removal rather than audited in later phases:
- `src/Module/Community/CommunityFeedPage.tsx` (831 lines) — not imported anywhere. `CommunityRoomPage.tsx` renders `@/components/feeds/CommunityFeedScreen` instead; this file appears to be a superseded earlier implementation left in place.
- `src/Module/ChatRoom/componets/main/MediaGallery.tsx` (362 lines) — not imported anywhere.
- `src/Module/ChatRoom/componets/VoiceLockedActionsRow.tsx` and `src/Module/ChatRoom/componets/VoicePreviewRow.tsx` — not imported anywhere (voice-recording UI now appears to be built inline inside `HoldToLockComposer.tsx`).
- `src/Module/ChatRoom/Storage/chatMediaMigration.ts` exports `runChatMediaMigrationIfNeeded()`, a one-time startup migration — but nothing in the codebase ever calls it. The migration it describes (moving stray files from `KIS/Media/Chat/*` back to `KIS/ChatMedia/*`) is likely never actually running, which is a latent correctness bug worth flagging to a later phase, not just a dead-code note.
