## Summary

All 61 assigned files were read and catalogued below. The single most important architectural finding for this scope: **almost none of the calls screens are React Navigation routes.** Only `CallJoinScreen` (deep-link handler, route `CallJoin`) is registered in `App.tsx`. Every other calls screen — `ActiveCallScreen`, `IncomingCallScreen`, `LobbyScreen`, `WaitingForHostScreen`, and `CallMiniBadge` — is mounted *imperatively* as a sibling of `{children}` inside the root-level provider at `/Users/nigel/dev/KIS/SocketProvider.tsx` (143KB, last touched by the recent bug-fix campaign), conditioned purely on `activeCall.state` (`incoming` / `waiting-for-host` / `lobby` / active-or-connecting / minimised). This is a *different* file from the 35-byte re-export shim at `src/SocketProvider.tsx` (`export * from '../SocketProvider'`) — easy to grep the wrong one. Any future audit pass that walks routes will miss the entire live-call UI; it has to be exercised by driving call state through the socket/`useSocket()` context instead. `src/components/calls/CallOverlay.tsx` is an explicit dead stub (`return null`, kept only to re-export two legacy types) — its own header comment says the real UI moved to `ActiveCallScreen`/`IncomingCallScreen`. `LobbyScreen` and `WaitingForHostScreen` looked orphaned on a naive repo-wide grep (no importer besides themselves inside `src/`) until the root `SocketProvider.tsx` import was found — they are live, just not discoverable via `src/`-only searches. One market component, `ProviderOrdersPage`, is deliberately registered under two separate route names (`MarketplaceProviderOrders` and `MarketplaceReceivedOrders`) pointing at the same component. Market screens are, by contrast, conventionally routed — all screen-level market files except the shop/product/service "drawers" (rendered as children of `ShopDashboardScreen` or `ProfileScreen`, not routes) have a `RootStack.Screen` entry in `App.tsx`, almost all using `options={{ presentation: 'modal' }}`.

Per-file detail follows. "Route name" is the literal `name=` string on the `RootStack.Screen` in `App.tsx` where one exists; otherwise it states how/where the component is actually mounted.
