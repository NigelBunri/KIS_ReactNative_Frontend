# Screens Inventory — Education & Insights

**Scope:** `src/screens/education/**` (25 files), `src/screens/insights/**` (20 files), `src/components/insights/**` (9 files).
**Inventoried:** 54 / 54 assigned files. No files unreachable. Audit status for every row is `NOT STARTED` (Phase 1 is inventory-only — no code was edited, no builds/tests run).

## Context already known (read before auditing — do not re-report as new)

- `docs/education-dashboard-redesign-progress.md` documents a **now-superseded** redesign of the old `EducationManagementModal.tsx` (single modal, state-machine navigation: hub → dashboard → module → detail). That modal and its state machine **no longer exist** — it was deleted in the "Education UX v2" rewrite. Its Phase-1 premium component kit (`EducationScreenScaffold`, `EducationWorkspaceHeader`, `EducationSectionCard`, `EducationMetricTile`, `EducationStatusBadge`, `EducationActionButton`, `EducationListCard`, `EducationEmptyState`, `EducationTimelineItem`) survived the deletion and was relocated to `src/screens/education/shared/components.tsx`, which is why nearly every provider/learner screen in this inventory imports from it.
- `docs/education-ux-v2-visual-and-broadcast-pass.md` documents the actual current architecture: real navigator destinations under `src/screens/education/{provider,learner}/`, a restored Broadcasts flow (`BroadcastsScreen.tsx` + `InstitutionProfileScreen.tsx`), and a restored offline-save feature (`useEducationOfflineStore`). It also flags known risks that still apply and should NOT be re-reported as new findings:
  - `EducationRevenuePreviewCard` (`src/components/profitability/...`) is a stub that always renders `null`.
  - `InstitutionProfileScreen` calls two institution-staff-scoped endpoints read-only from a learner context; unverified against live backend whether non-staff learners can read them (soft risk — screen degrades to empty sections, does not crash).
  - `CourseBuilderScreen`'s Curriculum tab and its three editors (`ContentEditor`, `AssessmentsEditor`, `LiveEditor`) plus `LearningPlayerScreen` were deliberately left on original inline styles — a styling-only pass, not a functional gap.
- Both docs confirm: all education screens reuse the existing `src/screens/broadcast/education/**` data layer (hooks, models, access utils) — that directory is **out of this scope** but is where most business logic / API-shape code actually lives. The files in `src/screens/education/**` are the presentation layer only.

## New observations from this inventory pass (not in either prior doc)

1. **`ProfileInsightsScreen.tsx` is orphaned.** It is not imported by `App.tsx`, not registered as a route in `src/navigation/types.ts`, and not referenced anywhere else in the codebase except a one-line comment in `src/network/routes/adminRoutes.ts`. It is fully built (uses `InsightLayout`, `useProfileInsights`, `useNotificationsSummary`) but appears unreachable in the live app. Needs a decision in a later phase: wire it to a route, or confirm it's intentionally dead and candidate for removal.
2. **`AdminDashboardScreen.tsx` and `AnalyticsDashboardScreen.tsx` are both thin wrappers around the same generic `InsightScreen.tsx`** (passing different `target`/`title`/`description`), yet they are registered as two separate routes (`AdminDashboard`, `AnalyticsDashboard`) reachable from different places. Worth checking in the UX pass whether these should visually/conceptually diverge or whether one is redundant.
3. Most of the heavier insights/admin screens (`AIIntegrationScreen`, `BridgeManagementScreen`, `MediaAssetManagerScreen`, `ModerationConsoleScreen`, `SurveyManagerScreen` — all 580–960 lines) use raw inline `StyleSheet.create` styling and hand-rolled `Modal`/`FlatList` patterns, not the shared `InsightLayout`/`components/insights` kit at all — that shared kit (`BarChart`, `DonutChart`, `KpiGrid`, `KpiTile`, `LineChart`, `TimeRangeSelector`, `TopItemsList`, `InsightSkeleton`) is only consumed by `InsightLayout.tsx`, which in turn is only used by `InsightScreen.tsx`, `PartnerInsightsScreen.tsx`, and `ProfileInsightsScreen.tsx`. The "CRUD/management" screens (Bridge, Media, Survey, Moderation, AI) are a visually distinct, unrelated family from the "read-only dashboard" screens (Analytics/Admin/Partner/Profile) despite living in the same folder — a likely source of visual inconsistency the UX pass should address.
4. Three education provider screens (`ProgramDashboardScreen`, `ClassDashboardScreen`, and implicitly `CourseBuilderScreen`) share an identical "one screen, internal tab bar, single detail-payload fetch" pattern by design (per their own header comments) — consistent, not a defect.
5. `src/screens/education/provider/course-builder/{AssessmentsEditor,ContentEditor,LiveEditor}.tsx` are not routes at all — they are tab-content components rendered inline by `CourseBuilderScreen.tsx`'s internal tab switch, and per the v2-visual-pass doc were deliberately left unstyled (original inline styles) as a low-risk-tolerance decision.

## Route-name cross-reference notes

All education routes (`Education*`) are registered in `App.tsx` (~lines 1945–1963) as `RootStack.Screen` entries, all with `presentation: 'modal'` and a shared `educationModalContentStyle`, and typed in `src/navigation/types.ts` (~lines 204–300). Linking paths for a subset are registered at `App.tsx` ~lines 1464–1470 (`EducationHome`, `EducationMyLearning`, `EducationCertificates`, `EducationInstitutionPicker`, `EducationCourseDetail`, `EducationInstitutionProfile`, `EducationInstitutionDashboard`).

Insights routes are scattered across three separate `App.tsx` regions rather than one contiguous block: `PartnerInsights` (~line 1582), the `AdminTools`/`ModerationConsole`/dashboard cluster (~lines 1615–1684), and the `AdminDashboard`/`AIIntegration`/`MediaAssetManager`/`SurveyManager` cluster (~lines 2029–2046). None of these are typed with a visible param list in the grep above except where noted — full param shapes were not individually re-verified per route in this inventory pass (out of scope for Phase 1; flag for the audit phase if param-contract mismatches are suspected).
